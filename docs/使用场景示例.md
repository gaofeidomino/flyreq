
完整可运行代码：`examples/basic/review/scenarios.mjs`。以下 TypeScript 片段适合接入实际业务，接口地址与响应类型应按业务修改。

## 1. 初始化与基础请求

```ts
import { setupFlyreq, flyreq } from 'flyreq'
interface Article { id: number; title: string }
setupFlyreq({
  backend: 'fetch',
  baseURL: 'https://api.example.com',
  token: () => sessionStorage.getItem('access_token'),
  retry: false,
})
const articles = await flyreq.get<Article[]>('/articles', {
  params: { page: 1, size: 20 },
})
const created = await flyreq.post<Article>('/articles', { title: 'Hello' })
```

默认业务协议为 `{code: 0, data, message}`。成功返回 data，业务失败抛出 BusError；`raw: true` 可以保留完整响应对象。HEAD、204、205 返回 undefined。

## 2. 缓存、并发请求合并与用户切换

```ts
import { flyreq, setRequestToken, resetFlyreqClient } from 'flyreq'
interface Profile { id: number; name: string }
const [first, second] = await Promise.all([
  flyreq.get<Profile>('/me', { cache: 30_000 }),
  flyreq.get<Profile>('/me', { cache: 30_000 }),
])
// 相同键共享正在执行的请求，成功结果缓存 30 秒。
setRequestToken('YOUR_ACCESS_TOKEN_HERE')
const currentUser = await flyreq.get<Profile>('/me', { cache: 30_000 })
// 注入后的认证信息与服务地址进入默认键，切换用户不会读到上一用户结果。
// 登出时还可以主动释放内存中的缓存与防重状态：
resetFlyreqClient()
setRequestToken(undefined)
```

使用动态 token getter 时，登出也要清除 getter 读取的存储。`resetFlyreqClient` 同时重置默认 retry 配置，之后可重新初始化。自定义缓存键应自行包含用户、服务地址、参数及正文等维度。

## 3. 防止重复提交

```ts
import { flyreq } from 'flyreq'
interface PaymentResult { paid: boolean }
const submit = (): Promise<PaymentResult> => flyreq.post(
  '/payments', { orderId: 123 },
  { idempotent: { duration: 5000 }, retry: false },
)
const results = await Promise.all([submit(), submit()])
```

防重窗口默认 5 分钟；上例改为 5 秒。失败响应不缓存，用户可重新提交。这里是当前进程/页面的防重，支付等关键业务仍需服务端幂等键与事务保障；跨设备、页面刷新和网络未知结果不能由前端缓存解决。

## 4. 重试读取请求

```ts
import { flyreq } from 'flyreq'
const data = await flyreq.get<unknown>('/reports', {
  retry: {
    maxCount: 3,
    delay: (attempt: number): number => Math.min(200 * 2 ** (attempt - 1), 2000),
  },
})
```

maxCount 是重试次数，3 表示最多执行 4 次。默认重试网络错误、HTTP 5xx 和 429，取消不会继续重试。写入请求应显式关闭重试，或结合服务端幂等协议制定策略。

## 5. 超时与手动取消

```ts
import { flyreq } from 'flyreq'
const controller = new AbortController()
const task = flyreq.get<unknown>('/slow-report', {
  timeout: 3000,
  signal: controller.signal,
})
// 用户离开页面时调用：controller.abort()
try { await task }
catch (error: unknown) { console.error(error) }
```

Fetch 现在同时执行 timeout 与外部 signal。适配器的错误类型不同：Fetch 通常是 AbortError/TimeoutError，Axios 为 AxiosError/CanceledError；业务层捕获 unknown 后再判断类型。同键并发调用共享底层请求，底层请求被取消可能使共享调用一并失败；需要独立取消时可以关闭 `cache.dedupeInFlight`，并确保键策略不会合并独立操作。

## 6. 限制并发和串行

```ts
import { createFetchRequestor, createParallelRequestor, createSerialRequestor } from 'flyreq'
const base = createFetchRequestor({ baseURL: 'https://api.example.com' })
const parallel = createParallelRequestor({ maxCount: 2, base })
await Promise.all(['/a', '/b', '/c'].map((url: string) => parallel.get(url)))
const serial = createSerialRequestor({ base })
await Promise.all([serial.post('/step-1', {}), serial.post('/step-2', {})])
```

这里返回底层 HttpResponse，读取结果使用 `await response.json<T>()`；需要业务协议解包可使用 busCall。串行请求即使前一项失败，也不会阻止后续队列继续执行。

## 7. Axios / XHR 与依赖注入

```ts
import { setupFlyreq, createXhrRequestor, defineRequestor, createHttpResponse } from 'flyreq'
import { createAxiosRequestor } from 'flyreq/axios'
setupFlyreq({ backend: createAxiosRequestor(), baseURL: 'https://api.example.com' })
// 浏览器中也可以：setupFlyreq({ backend: createXhrRequestor() })
const mock = defineRequestor(async (config) => createHttpResponse({
  status: 200, statusText: 'OK', headers: {}, url: config.url,
  data: { code: 0, data: { mocked: true }, message: 'ok' },
}))
setupFlyreq({ backend: mock })
```

createHttpResponse 的 data 应为已解析的数据；JSON 字符串值不会再次解析为数字或对象。

## 8. 持久化缓存与特殊正文

```ts
import { createCacheRequestor, createFetchRequestor, createStorageStore } from 'flyreq'
const req = createCacheRequestor({
  base: createFetchRequestor({ baseURL: 'https://api.example.com' }),
  store: createStorageStore(),
  duration: 60_000,
})
const response = await req.get('/public-settings')
```

持久化缓存适合公开、可序列化的数据。上传 FormData/Blob 等特殊正文时，普通请求不受影响；若启用自动缓存或防重，需提供能够完整代表文件内容和身份的自定义 key，否则会明确报错，避免不同文件被误合并。

## 9. 代码生成与手动补丁

接口配置示例：

```json
{"endpoints":{"article":{"search":{"path":"/articles/search","method":"POST","pager":true},"detail":{"path":"/articles/{id}","method":"GET","cache":true}}}}
```

```sh
pnpm --filter flyreq exec node dist/cli.js gen ./api.json -o ./generated
```

POST 分页现在生成 `flyreq.post(url, undefined, options)`，分页放在 options.params；若接口还要求正文，可在 overrides 中编写包装函数，直接调用 flyreq.post 并传入正文。路径参数会经过 encodeURIComponent，生成目录与手工 overrides 分开维护。
